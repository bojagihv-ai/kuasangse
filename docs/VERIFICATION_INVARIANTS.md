# 작업 완료 절대 불변 규칙

이 문서는 이 저장소에서 작업을 진행하거나 완료를 보고할 때 반드시 지켜야 하는 사용자 고정 규칙이다. 아래 두 증거가 모두 없으면 완료·해결·검증 완료로 보고하지 않는다.

## 1. 실제 프로그램 실행·결과 read-back

- 버튼·탭·워크플로우를 고친 뒤 사용자의 실제 프로그램 화면에서 대상 컨트롤을 직접 활성화한다.
- 웹앱은 실제 Chrome의 조립공장 탭에서 실행한다. 자동 테스트, 격리 브라우저, HTTP 200, DOM 구조 확인, 코드 리뷰만으로는 실제 검증으로 인정하지 않는다.
- 실행 전 상태와 실행 후 상태를 같은 화면에서 읽는다. 진행 작업이면 `대기 → 실행 중 → 완료/실패`의 변화를 확인한다.
- 이미지 작업은 이미지 카드가 실제로 생기고 `img.complete === true`, `naturalWidth > 0`인 것을 확인한다. 크게보기 같은 후속 UI가 있으면 직접 열고 닫아 결과를 다시 읽는다.
- 확인하지 못한 경우 보고 문구는 `실제 화면 결과 미확인` 또는 정확한 차단 원인으로 제한한다.

## 2. 상태 A 보존 + 요청 변경만 적용

- 작업 시작 시점의 상태 A를 먼저 기록한다: 입력값, 선택값, 대표/컷/생성 이미지, 후보, 현재 단계, 로그, 작업파일 식별자.
- 변경 결과는 A의 모든 항목을 그대로 보존한 A+B여야 한다. B와 무관한 자산·상태를 지우거나 stale snapshot으로 덮어쓰지 않는다.
- `새 작업`, 명시적 초기화, 삭제, 교체를 사용자가 실행한 경우에만 해당 범위를 비운다. Ctrl+F5·재연결·코드 수정은 기존 자료를 비우는 동작이 아니다.
- 변경 전후의 핵심 상태를 회귀 비교하고, 차이가 요청 범위를 벗어나면 실패로 기록한 뒤 원인을 고친다.

## 완료 보고 게이트

완료 보고에는 다음을 함께 기록한다.

1. 실제 프로그램에서 누른 대상과 결과 화면 read-back 증거
2. 상태 A에서 보존된 항목과 요청으로 추가된 B
3. 실행 명령·테스트 로그·스크린샷 또는 실제 화면 확인 시각

셋 중 하나라도 없으면 작업은 진행 중이며 완료가 아니다.

## 3. 기계적으로 강제되는 Chrome 인계 증거

`npm run verify:handoff`는 이제 `output/debug-evidence/required-fields-ab-preservation.json`을 반드시 읽는다. 이 파일은 실제 사용자 Chrome에서 같은 작업을 대상으로 작성해야 하며, 다음 조건을 모두 만족하지 않으면 인계를 차단한다.

- `schema=kuasangse.actual-chrome-required-fields.v1`, `browser=Chrome`
- 수동으로 값을 다시 입력하지 않은 기존 A 상태(`manualEntry=false`, `newWorkClicked=false`)
- 실제 물리 키 입력 `Ctrl+F5` 실행(`physicalCtrlF5=true`)
- 실행 전후 10개 필드의 화면 read-back과 동일성(`screenReadback=true`, `unchanged=true`)
- 실행 전후 스크린샷 2개와 24시간 이내 검증 시각

자동 테스트·격리 브라우저·HTTP 응답만으로 이 증거 파일을 만들거나 완료로 대체하지 않는다.
