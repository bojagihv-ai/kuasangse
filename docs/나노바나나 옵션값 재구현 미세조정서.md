# 옵션표 생성 하네스 레시피

작성일: 2026-06-16

이 문서는 옵션 선택 이미지 생성이 다시 흐트러지지 않도록, 현재 성공한 생성 구조를 재구현 가능한 값으로 고정해 둔 기록이다.

## 핵심 결론

성공한 방식은 프롬프트만으로 한 것이 아니다.

실제 구조는 다음 3개를 함께 사용한다.

1. 프롬프트 본문: 제품 보존, 셀 매핑, 색상 잠금, 샘플 이미지 사용 범위, 이전 시트 연속성 규칙을 글로 명시한다.
2. 참조 이미지 첨부 순서: 코드가 제품 이미지, 샘플 이미지, 이전 생성 결과 이미지를 정해진 순서로 API에 붙인다.
3. 이전 결과 재참조: 2장 이상 생성할 때 첫 번째 성공 결과를 다음 시트의 연속성 샘플로 다시 첨부한다.

Gemini / Nano Banana API에는 `style_template_sample`, `previous_sheet_continuity_sample` 같은 역할명이 네이티브 역할로 전달되지 않는다. 실제 API에는 이미지가 순서대로 `inline_data`로 들어간다. 역할은 프롬프트 안에서 "Reference image N = ..." 형태로 설명하고, 코드는 그 순서가 깨지지 않게 이미지를 배열한다.

## 코드 위치

- 호출 래퍼: `app.html`의 `generateWithSelectedImageModel(...)`
- Gemini 이미지 호출: `app.html`의 `GeminiAPI.generateImage(...)`
- 옵션표 시트 분할: `app.html`의 `getOptionOutputSheets(...)`
- 옵션표 프롬프트 생성: `app.html`의 `buildOptionSelectionSheetPrompt(...)`
- 옵션표 생성 루프: `app.html`의 `optGenerateOptionImages(...)`

## 시트 분할 규칙

`전체 옵션표` 방식에서는 4개 단위로 나눈다.

- 옵션 1-4: `전체 옵션표 1/2`
- 옵션 5-8: `전체 옵션표 2/2`
- 옵션 20개: 4개씩 5장

2개씩 묶는 방식은 2개 단위로 나눈다.

## 참조 이미지 첨부 순서

4개 옵션 시트 기준:

1. Reference image 1 = Cell 1 제품 이미지
2. Reference image 2 = Cell 2 제품 이미지
3. Reference image 3 = Cell 3 제품 이미지
4. Reference image 4 = Cell 4 제품 이미지
5. Reference image 5 = 사용자가 지정한 샘플 옵션표 이미지, 있을 때만 첨부
6. Reference image 6 = 같은 배치에서 바로 직전에 성공한 옵션표 이미지, 두 번째 시트부터 첨부

샘플 이미지가 없으면 두 번째 시트의 이전 결과 이미지는 Reference image 5가 된다.

## API로 실제 들어가는 형태

Gemini / Nano Banana 호출에서 실제 `parts` 구성은 다음 순서다.

1. `{ text: fullPrompt }`
2. `{ inline_data: 첫 번째 제품 이미지 }`
3. `{ inline_data: 나머지 제품 이미지들 }`
4. `{ inline_data: 샘플 옵션표 이미지 }`, 있을 때만
5. `{ inline_data: 이전 생성 결과 이미지 }`, 두 번째 시트부터

즉, 코드는 이미지 역할을 직접 전달하지 않고 이미지 순서를 고정한다. 프롬프트가 그 순서를 역할로 해석하게 한다.

## Gemini 생성 설정

현재 Gemini 이미지 호출은 다음 설정을 사용한다.

- `temperature`: `0.8`
- `responseModalities`: `["TEXT", "IMAGE"]`
- 기본 크기 힌트: `860px wide`
- 커스텀 크기가 설정되어 있으면 `Exact size: {width}px wide × {height}px tall`
- 활성 이미지 지시문, 브랜드 프리셋, 레이아웃 프리셋도 최종 프롬프트 뒤에 붙는다.

## 제품 보존 하네스

아래 규칙은 톤앤매너보다 먼저 적용된다.

1. 업로드한 제품 사진이 실제 판매 상품 기준이다.
2. 실루엣, 파우치 세로/가로 비율, 입구 형태, 원단 질감, 색상, 끈 위치, 비즈/자수 장식, 여밈, 봉제선, 고유 장식을 바꾸면 안 된다.
3. 새 제품을 만들면 안 된다. 장식띠, 새 자수, 제품 몸통의 새 라벨, 손잡이, 추가 끈, 새 여밈을 만들면 안 된다.
4. 옵션명은 색상 명령이 아니다. 옵션명이 원본 색상과 충돌하면 원본 제품 색상을 유지한다.
5. 원본 배경, 테이블 색, 종이 배경, 촬영 각도, 대각선 구도는 제품 정체성이 아니다. 이것들은 공통 템플릿에 맞춰 교체/정리한다.
6. 모든 셀은 같은 그리드, 카드 크기, 제품 스케일, 제품 각도, 세워진 방향, 여백, 조명 방향, 그림자, 하단 라벨 영역을 공유한다.
7. 원본이 누워 있거나 대각선이어도 샘플/템플릿이 세워진 구도면 제품만 보존하고 세운 구도로 다시 배치한다.
8. 톤/스타일이 제품 보존과 충돌하면 톤/스타일을 무시하고 원본 제품을 우선한다.
9. 최종 이미지는 광고 히어로컷이 아니라 옵션 선택표다.

## 옵션명 색상 충돌 잠금

프롬프트에 아래 규칙이 들어간다.

- 옵션명은 라벨 텍스트일 뿐 시각 명령이 아니다.
- "노랑"이라고 적혀 있어도 원본 이미지가 초록이면 제품은 초록으로 유지하고 라벨만 "노랑"으로 출력한다.
- 각 셀은 자기 Reference image만 사용한다.
- 셀을 바꾸거나 옵션명을 바꾸거나 다른 이미지의 라벨을 가져오면 안 된다.

## 샘플 이미지 하네스

샘플 이미지가 있을 때 샘플은 다음 항목의 기준으로만 사용한다.

- 제품 방향과 각도 규율
- 그리드 구조와 카드 비율
- 카드 둥글기, 테두리 두께, 간격
- 배경 톤과 조명 분위기
- 그림자 방향, 부드러움, 강도
- 하단 라벨 pill 모양, 위치, 크기, 글자 느낌, 여백 리듬

샘플에서 복사하면 안 되는 항목:

- 제품 자체
- 제품 색상
- 옵션명
- 제품 장식
- 샘플 이미지 안의 텍스트 내용

제품 색상/형태/장식/끈/원단은 현재 셀의 제품 이미지가 유일한 기준이다.

## 이전 결과 연속성 하네스

2장 이상으로 나뉠 때, 직전에 성공한 옵션표 결과 이미지를 다음 시트에 첨부한다.

이전 결과 이미지는 다음 항목의 기준이다.

- 캔버스 크롭과 외부 여백
- 카드 테두리 색, 두께, 둥글기, 간격
- 제품 세워짐, 중앙 배치, 스케일, 그림자
- 라벨 pill 너비, 높이, 위치, 테두리, 텍스트 스타일
- 배경색과 조명

두 번째 시트는 새 디자인이 아니라 같은 옵션 선택표 세트의 다음 페이지처럼 보여야 한다.

## 생성 방식별 차이

### 전체 나노바나나 생성

- 제품, 카드, 배경, 옵션명 글자까지 이미지 모델이 한 번에 생성한다.
- 프롬프트에 `CONTENT MODE - FULL IMAGE`가 들어간다.
- 라벨 오타/순서 오류 위험은 있지만, 통합된 완성 이미지 퀄리티가 높다.

### 이미지 생성 + 글자 따로

- 이미지 모델은 제품/카드/배경만 만들고 라벨 영역을 비운다.
- 앱이 이후 고정 좌표로 정확한 옵션명을 오버레이한다.
- 프롬프트에 `APP POST-PROCESS OVERLAY` 기록이 추가 저장된다.

### 글자/레이아웃만

- 이미지 생성 없이 레이아웃 계획과 옵션 라벨만 만든다.

## 결과에 저장되는 재현 정보

각 생성 결과에는 다음 정보가 저장된다.

- `prompt`: 최종 프롬프트 전문
- `modelId`: 사용 모델 ID
- `modelLabel`: 사용자 표시용 모델명
- `pipelineId`, `pipelineName`
- `contentMode`: 전체 이미지형 / 이미지+글자 따로 / 글자만
- `mode`: RAW 사진 보정 / 정리된 옵션 사진
- `tonePresetId`, `tonePresetName`, `tone`
- `styleSampleName`, `styleSampleId`, `styleSampleLibraryId`
- `continuitySampleName`
- `sourceName`
- `optionNames`
- `createdAt`

다음번 재구현은 이 저장값 중 `prompt`, `modelId`, `contentMode`, `mode`, `tone`, `styleSampleName`, `continuitySampleName`, 이미지 첨부 순서가 같으면 최대한 같은 방식으로 재현된다.

## 재구현 체크리스트

1. 같은 제품 이미지 순서를 유지한다.
2. 같은 옵션명 순서를 유지한다.
3. 같은 `전체 나노바나나 생성` 또는 `이미지 생성 + 글자 따로` 방식을 선택한다.
4. 같은 RAW/정리된 사진 모드를 선택한다.
5. 같은 톤앤매너 프리셋을 선택한다.
6. 같은 샘플 이미지를 선택한다.
7. 4개 단위 시트 분할을 유지한다.
8. 두 번째 시트부터 이전 성공 결과 이미지를 연속성 샘플로 첨부한다.
9. 결과 카드의 최종 프롬프트와 생성 모델을 확인한다.
10. 실패 셀이 생기면 실패 시트를 샘플로 삼지 말고, 성공한 이전 시트를 연속성 기준으로 다시 생성한다.
